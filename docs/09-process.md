# 09. 작업 순서

좋은 결과가 나온 작업은 모두 같은 순서를 거쳤습니다. 순서를 건너뛰고 바로 그리기 시작한 시안은 대부분 반려됐습니다.

## 1. 용도를 한 문장으로 적습니다

"누가 이 작업물을 보고 무엇을 하게 되는가"를 적습니다. 포스터라면 지나가는 사람이 날짜를 기억하는 것, 소개 자료라면 처음 듣는 사람이 규모와 일정을 파악하는 것입니다.

이 문장이 틀리면 뒤의 모든 작업이 헛됩니다. 행사 자체를 소개하는 자료를 요청받고 후원 제안서 구성으로 만들었다가 전부 다시 만든 일이 있었습니다.

## 2. 실제 작업 한두 개를 기준으로 삼습니다

머릿속에 떠오르는 구성은 가장 흔한 구성입니다. 그리기 전에 실제 디자이너가 만든 작업을 찾습니다.

- 서체 사용 사례를 모아 둔 아카이브, 공연과 전시 포스터, 행사 아이덴티티 사례에서 찾습니다.
- 발표 자료와 IR 덱은 디자이너가 만든 덱에서 찾습니다 (Behance, Dribbble, 노트폴리오의 피치덱 프로젝트). 제품 웹사이트의 히어로 화면을 덱의 기준으로 삼으면 "왜 맨날 그 사이트만 보느냐, 디자이너가 만든 덱을 찾아야지"라는 평을 받습니다.
- 한두 개만 고릅니다. 여러 개를 섞으면 어느 것의 장점도 남지 않습니다.
- 고른 작업에서 가져올 기법을 이름으로 적습니다. "분위기가 좋다"가 아니라 "가로 2분할 색면, 단어 중간에서 끊는 큰 세리프, 모서리의 작은 정보"처럼 적습니다.
- 이름으로 적을 수 없으면 아직 참고한 것이 아닙니다.

기법 목록의 예입니다.

| 기준 작업의 종류 | 가져온 기법 |
| --- | --- |
| 글자만으로 된 행사 포스터 | 가로 2분할 색면, 화면을 넘는 크기의 세리프 제목, 단어 중간 줄바꿈, 네 모서리의 작은 정보 |
| 공연 포스터 | 사실 정보를 촘촘히 담은 정보 띠, 대표 이미지 뒤에 깔린 같은 계열 색의 큰 제목, 세로쓰기 제목, 사물의 그림자 |
| 기술 행사의 아이덴티티 | 무채색 바탕, 큰 글자, 해마다 바꾸는 모티프 하나 |

### 구도를 적고 그대로 옮깁니다

레퍼런스를 열어 보고도 결과는 평소 하던 구도로 돌아가기 쉽습니다. 사업 발표 덱의 첫 장 시안들이 배경만 다를 뿐 모두 "왼쪽 글, 오른쪽 이미지"였고, "레퍼런스의 뭘 참고했다는 거냐, 다 똑같다"는 평을 받았습니다. 기법과 분위기만이 아니라 구도를 옮겨야 합니다.

레퍼런스 한 장을 크게 띄워 놓고 네 가지를 적습니다.

| 볼 것 | 적는 내용 |
| --- | --- |
| 이미지의 자리 | 화면 전체를 덮는 사진인지, 한쪽에 놓인 물체인지, 위쪽에 흩어진 카드인지 |
| 제목의 크기와 굵기 | 화면 폭의 얼마를 가로지르는지, 가는지 굵은지, 이미지 위에 겹치는지, 화면의 어느 높이에 있는지 |
| 작은 정보의 자리 | 네 모서리, 위아래 띠, 한쪽 세로 열 가운데 어디에 몇 줄인지 |
| 카드와 물체의 분포 | 몇 개가 화면의 어느 범위에 퍼져 있는지, 정면인지, 얼마나 겹치는지 |

- 시안 하나에 레퍼런스 하나의 구도를 가져오고, 시안 이름에 그 구도를 적습니다 (예: "전면 사진 위 거대한 가는 제목 (테니스 IR 표지 구조)").
- 만든 시안을 레퍼런스 옆에 같은 크기로 놓고 네 가지를 하나씩 비교합니다. 하나라도 평소 구도로 돌아갔으면 이름에 "보류"를 붙여 남기고 다시 만듭니다. 레퍼런스를 옮긴다며 만든 시안이 다시 좌우 분할이 된 일이 있었습니다.
- 옮기는 것은 구도입니다. 사진, 문구, 색은 우리 내용으로 채웁니다.

## 3. 서체를 먼저 정합니다

배치보다 서체가 먼저입니다. 서체가 바뀌면 글자 폭이 달라져 배치를 다시 해야 합니다.

- 실제 문구로 후보 판을 만듭니다. 같은 문구를 후보 서체 여러 개로 나란히 놓습니다.
- 굵기도 후보에 넣습니다. 같은 서체라도 큰 크기에서는 Light와 Black이 다른 서체처럼 읽힙니다 ([03](03-typography.md)).
- 작업 도구에서 쓸 수 있는 서체인지 먼저 확인합니다.
- 고르는 사람이 판의 몇 번째를 가리키는지 확인합니다. 비교 이미지가 여러 장이면 어느 이미지의 몇 번째인지 되묻습니다.

## 4. 그리드와 수치를 정합니다

여백, 열, 간격 단계, 크기 단계를 숫자로 적어 놓고 시작합니다 ([04](04-layout-and-flow.md), [03](03-typography.md)). 숫자가 먼저 있으면 이후의 모든 좌표가 계산으로 나옵니다.

## 5. 방향이 다른 시안을 만듭니다

- 시안은 두세 개를 만들되 서로 다른 발상이어야 합니다. 같은 구성에서 색만 바꾼 것은 시안 하나입니다.
- 시안마다 무엇을 시험하는지 한 줄로 적습니다. "사진 없이 글자만", "사진을 전면에", "피사체와 글자를 겹침"처럼 적습니다.
- 반려된 시안은 지우지 않고 한쪽에 모아 둡니다. 나중에 왜 바뀌었는지 설명할 근거가 됩니다. 지울 때는 요청한 사람에게 먼저 묻습니다.
- 여러 장짜리 작업은 덱 줄에 지금 고른 장만 두고, 장마다 버전 섹션을 만들어 이전 버전과 시안을 "장 · v번호 또는 시안 번호 · 날짜 · 무엇인지"로 모읍니다. 원본을 고쳐 놓고 복사본만 숨겨 두면 "이전 디자인을 왜 날리느냐"는 평을 받습니다. 고른 뒤에만 덱 줄로 옮깁니다.
- 요청이 여러 장을 가리키는지 애매하면 분명히 지목된 장만 바꾸고, 나머지는 시안으로 따로 제안합니다.

## 6. 실제 크기로 렌더링해 확인합니다

수치와 코드만 보고 끝내지 않습니다. 이미지로 뽑아 두 가지 크기로 봅니다.

| 크기 | 보는 것 |
| --- | --- |
| 100퍼센트 | 글자 겹침, 줄바꿈, 가장자리 품질, 정렬 어긋남 |
| 손톱 크기로 축소 | 주인공이 먼저 보이는지, 묶음이 몇 개로 보이는지 |

여러 장짜리 작업은 모든 장을 한 화면에 늘어놓은 이미지를 따로 만듭니다. 고정 요소의 위치가 장마다 같은지 한눈에 보입니다.

자주 걸리는 것들입니다.

- 문구를 바꾼 뒤 옆 요소와 겹침
- 긴 라벨 하나 때문에 열 폭이 깨짐
- 큰 글자의 왼쪽 끝이 작은 글자보다 들어가 보임
- 빗금이나 내려쓰는 획이 아래 줄과 닿음

## 7. 피드백을 글자 그대로 읽습니다

피드백은 해석하지 않고 말한 그대로 받아들입니다.

| 들은 말 | 잘못된 대응 | 맞는 대응 |
| --- | --- | --- |
| "잘리는 게 별로다" | 자르는 모양을 다른 모양으로 바꿈 | 자르지 않음. 사진을 전면에 둠 |
| "AI 같다" | 효과를 더함 | 기본값을 찾아 걷어 냄. 서체, 클립아트, 가운데 정렬 순으로 확인 |
| "이게 무슨 말이냐" | 설명 문장을 덧붙임 | 그 표현을 버리고 구체적인 말로 바꿈 |
| "단순했으면 좋겠다" | 요소를 줄이고 끝냄 | 요소를 줄이고 남은 것의 정밀도를 올림 |
| "여백이 이상하다" | 한 요소를 조금 옮김 | 위아래 여백을 같게 하고 묶음 전체를 다시 짬 |
| "배경에 오브제가 없는 느낌" | UI 카드를 더 쌓거나 기울기를 더함 | 실제 물체를 둠. 3D 기기 렌더, 실사 합성, 사물 은유 ([12](12-objects-and-renders.md)) |
| "이전이 훨씬 좋았다" | 새 안을 더 다듬음 | 이전 버전을 바로 덱 줄로 되돌리고 새 안은 버전 섹션에 남김 |
| "부록이 너무 많다" | 글자를 줄여 장마다 더 담음 | 분류별 네 장 안팎으로 묶고 분류 이름을 쪽 번호 자리에 적음 ([11](11-pitch-deck.md)) |
| "다양하게 뽑아 줘" | 같은 구성의 변형 여러 개 | 발상이 다른 시안 다섯 개 이상, 시안마다 시험하는 것을 이름에 적음 |
| "레퍼런스의 뭘 참고했다는 거냐", "다 똑같다" | 배경 사진이나 물체만 바꿈 | 레퍼런스의 구도를 네 가지(이미지 자리, 제목 크기와 굵기, 작은 정보 자리, 카드 분포)로 적고 그대로 옮김. 시안 이름에 가져온 구도를 적음 |
| "폰트가 두껍고 이상하다" | 같은 서체를 한 단계 가늘게 | 실제 문장으로 서체판을 만들어 서체와 굵기 후보 여덟 개 안팎을 보여 주고 번호로 고르게 함 ([03](03-typography.md)) |
| "사업 계획서에 저런 말을 쓰느냐" | 구어체 훅의 단어만 바꿈 | 문제 두 가지를 대구로 한 문장에 담고, 근거 두 줄로 받침 ([11](11-pitch-deck.md)) |
| "로고를 모든 곳에, 안 보일 수 있으니 확인하면서" | 밝은 장 하나에서만 확인 | 모든 장의 같은 자리에 두고, 장마다 렌더에서 로고 주변을 잘라 확대해 확인 ([11](11-pitch-deck.md)) |
| "어깨가 잘리고, 머리와 상반신 비율이 다르다" | 아래와 옆을 더 세게 녹임 | 얼굴 박스로 얼굴 폭과 높이를 맞추고 타원으로 녹임 ([12](12-objects-and-renders.md) 4절) |
| "왼쪽으로 치우쳐 보인다" | 열마다 가운데 정렬로 바꿈 | 무게 중심과 오른쪽 빈 띠를 재고, 첫 열은 제목의 왼쪽 끝선에 둔 채 마지막 열의 가장 긴 줄이 오른쪽 여백선에 닿도록 열 간격을 넓힘 ([08](08-slides.md)) |

같은 지적을 두 번 받으면 고친 방향이 틀린 것입니다. 조금 더 고치지 말고 그 방식을 버립니다.

요청한 사람이 직접 고친 부분은 의도한 것입니다. 다음 작업에서 원래대로 되돌리지 않습니다.

## 8. 점검표로 마무리합니다

내보내기 전에 [점검표](../checklists/review.md)를 한 번 돕니다.

## 도구를 쓸 때 겪은 것

- 클라우드에서 도는 디자인 도구는 로컬 서체를 쓰지 못합니다. 외곽선으로 바뀐 글자는 다시 입력할 수 없습니다.
- 벡터를 붙여 넣은 뒤 배율 조정으로 크기를 맞추면, 열려 있는 다른 화면에 반영되지 않는 경우가 있었습니다. 경로 좌표를 최종 크기로 계산해 새로 만드는 쪽이 안전했습니다.
- 도구가 주는 미리보기와 서버에서 렌더링한 이미지를 둘 다 확인합니다.
- 큰 글자를 정렬할 때는 글자 상자가 아니라 렌더링된 잉크 경계 좌표를 읽어서 맞춥니다.

## AI 에이전트에게 맡길 때

- 이 저장소의 문서 가운데 해당하는 것을 함께 넘깁니다. 최소한 [02](02-ai-look.md)와 [점검표](../checklists/review.md)를 넘깁니다.
- 서체, 그리드 수치, 강조색, 금지 항목을 요청에 적습니다.
- 기준으로 삼을 실제 작업을 주고, 가져올 구도와 기법을 먼저 적게 합니다. 시안을 받으면 레퍼런스 옆에 놓고 구도가 같은지 봅니다.
- 결과를 이미지로 렌더링해 스스로 확인하게 하고, 그 이미지를 함께 받습니다.
- 통과 여부는 사람이 이미지를 보고 정합니다.
