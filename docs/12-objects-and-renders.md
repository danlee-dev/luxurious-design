# 12. 배경의 물체: 기기 렌더, 실사 합성, 사물, 인물

디자이너가 만든 덱을 보면 배경에 손에 잡히는 물체가 있습니다. 테니스 테크 IR 덱의 표지는 공을 크게 잡은 매크로 사진 위에 헤드라인을 얹었고, 농업 스타트업 덱은 오려 낸 양 한 마리를 슬라이드 옆에 세웠습니다 ([references](references.md)). UI 카드만 쌓은 화면은 아무리 기울이고 흐려도 비어 보입니다.

물체를 만드는 방법은 네 가지입니다. 어느 방법이든 물체가 정보를 담아야 합니다. 화면에 실제 내용이 있거나, 라벨에 실제 값이 적혀 있어야 합니다.

| 방법 | 맞는 경우 | 장점 | 주의 |
| --- | --- | --- | --- |
| 1. 3D 기기 렌더 | 제품 화면을 노트북, 태블릿, 휴대폰에 넣어 보여 줄 때 | 화면 내용이 정확하고 빛과 질감이 실물 같음 | 배경 색 맞춤, 화면 비율 |
| 2. 실사 사진에 화면 합성 | 3D 도구가 없거나 특정 구도의 사진이 필요할 때 | 사진의 공기감 | 원근 맞춤, 초록 번짐 |
| 3. 사물 은유 | 서비스가 다루는 대상을 한눈에 보여 줄 때 | 기억에 남음 | 장식으로만 읽히지 않게 라벨에 정보 |
| 4. 오린 인물 | 팀 소개, 인용 | 얼굴이 크게 보이고 배경과 이어짐 | 잘린 어깨의 경계 |

## 1. 3D 기기 렌더

기기 모델에 실제 화면 이미지를 붙이고 스튜디오 조명으로 렌더합니다. 기기 모델과 조명, 카메라를 지원하는 도구라면 어느 것이든 같은 원리입니다 (자체 렌더러, Blender, Spline 등).

설정값은 1920×1080 슬라이드의 배경으로 쓴 렌더에서 확인한 것입니다.

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 조명 | 밝은 스튜디오, 바닥과 접지 그림자 | 종이색 덱과 이어집니다. 어두운 덱이면 어두운 무대 |
| 화면 빛 | 노트북 키보드에 화면 빛을 받게 함 | 키 윗면이 화면 쪽으로 밝아져야 실물로 읽힙니다 |
| 렌즈 | 비스듬한 구도 70mm, 정면 120mm | 망원일수록 원근 왜곡이 줄어 제품 사진처럼 보입니다 |
| 조리개 | f/5.6~8 | 화면 글자가 흐려지지 않습니다 |
| 기기 위치 | 화면 오른쪽 절반, 제목 자리를 비움 | 왼쪽에 제목, 오른쪽에 물체 |
| 마감 | 밝은 덱에는 은색, 어두운 덱에는 검은색 | 배경과 대비 |

- 정면에서 키보드를 숨기려면 카메라를 키보드 높이에 두고 망원으로 멀리서 찍습니다 (120mm, 기기 폭의 약 5배 거리). 화면 가운데 높이에서 찍으면 키보드 윗면이 띠처럼 보입니다.
- 화면 이미지는 기기 비율로 만듭니다. 노트북은 약 16:10, 태블릿은 4:3입니다. 비율이 다르면 아래 줄이나 오른쪽 글자가 잘립니다.
- 화면 속 글자는 렌더에서 작아집니다. 슬라이드에서 화면 폭이 550px 안팎이면 원본 UI의 글자를 보통보다 2~3배 크게 디자인합니다.
- 렌더는 영상으로 내보낸 뒤 프레임을 뽑으면 해상도 손실이 없습니다 (`ffmpeg -ss 1.5 -i film.mp4 -frames:v 1 still.png`).

### 배경 맞추기

- 렌더 배경의 색을 재서 덱 바탕색이 되도록 채널마다 배율을 곱합니다. 예: 렌더 배경 (234, 233, 230)을 바탕색 (244, 243, 239)으로 맞추려면 약 1.04배입니다.
- 스튜디오 배경은 가운데가 조금 더 밝습니다. 렌더를 옆으로 밀어 배치하면 끝에서 경계가 보입니다. 렌더를 키워 슬라이드 전체를 덮게 하고 기기를 원하는 자리로 보냅니다. 확대는 1.3배 안에서 합니다.

## 2. 실사 사진에 화면 합성

1. 화면이 단색 초록(크로마키)인 기기 사진을 구합니다. 생성 이미지라면 프롬프트에 "화면은 단색 초록, 로고와 글자 없음, 바탕은 따뜻한 회백색, 빛은 왼쪽 위"를 넣습니다.
2. 초록 영역의 네 꼭짓점을 찾습니다. 좌상은 x+y 최소, 우하는 x+y 최대, 우상은 x−y 최대, 좌하는 x−y 최소입니다.
3. 꼭짓점을 중심에서 바깥으로 4px 키운 뒤 화면 이미지를 원근 변환(호모그래피)으로 붙입니다. 합성은 원본의 2배 해상도에서 합니다. 그래야 화면 글자가 선명합니다.
4. 초록의 정도를 마스크로 써서 화면만 바꿉니다. 경계에 남은 초록은 G 값을 R, B 쪽으로 낮춰 지웁니다.
5. 화면을 0.975배로 살짝 낮추고 대각선 반사광을 4% 안팎 얹습니다. 순백 화면은 사진 속에서 떠 보입니다.
6. 기기를 오려 슬라이드에 올리고 바닥 그림자를 새로 깝니다. 그림자 방향은 사진 속 빛의 반대쪽입니다.

[tools/screen_warp.py](../tools/README.md#screen_warppy)가 2~5단계를 합니다.

## 3. 사물 은유

서비스가 다루는 대상을 손에 잡히는 사물로 바꿉니다. 녹화 강의가 쌓인 상황은 비디오테이프 더미로 보여 줄 수 있습니다. 테이프마다 라벨에 과목과 재생 시간을 적으면 장식이 아니라 정보가 됩니다.

- 생성 이미지는 라벨을 비워 둡니다. 생성 모델이 쓴 글자는 깨집니다.
- 정면에서 찍은 구도로 요청합니다. 라벨에 원근이 없어야 글자를 얹기 쉽습니다.
- 라벨 위치는 이미지에서 찾습니다. 밝은 사각형이 행마다 이어지는 구간을 읽으면 라벨마다 좌표가 나옵니다. 그 좌표에 디자인 도구에서 글자를 얹습니다.
- 라벨 글자는 슬라이드 기준 21~22로 둡니다. 왼쪽에 이름, 오른쪽 끝에 숫자를 맞춥니다.

## 4. 오린 인물

증명사진을 그대로 쓰면 회색 배경의 상자가 됩니다. 인물을 오려 종이 위에 세웁니다.

1. 피사체를 분리합니다. macOS의 피사체 분리를 쓰는 [tools/lift.swift](../tools/README.md#liftswift)가 머리카락까지 깨끗하게 분리했습니다.
2. 아래쪽 45%를 녹입니다. 알파에 (1−t)^1.8을 곱합니다. t는 녹이기 시작한 높이에서 아래 끝까지의 비율입니다.
3. 어깨 쪽 좌우 22%를 녹입니다. 증명사진은 어깨가 양옆에서 잘려 있어서, 그대로 두면 세로 경계가 남아 다시 상자처럼 보입니다. 머리 높이에는 적용하지 않고 아래로 갈수록 세게 합니다.
4. 이름은 녹은 가슴 위, 알파가 0.2 아래로 떨어진 높이에 겹칩니다. 어두운 옷 위에 검은 글자가 오면 읽히지 않습니다.
5. 사진은 아래 끝을 같은 기준선에 맞춥니다. 같은 배율의 증명사진이면 머리 높이가 자연스럽게 다릅니다.

[tools/fade_edges.py](../tools/README.md#fade_edgespy)가 2, 3단계를 합니다.

## 5. 생성 이미지를 쓸 때

- 브랜드 로고, 글자, 사람 얼굴은 생성하지 않습니다.
- 바탕은 덱 바탕색과 같은 계열로, 빛은 덱의 다른 장과 같은 방향으로 요청합니다.
- 100% 크기로 보고 키 개수, 포트 위치, 경첩처럼 구조가 이상한 곳이 없는지 확인합니다.
- 생성 비용이 드는 도구라면 쓴 뒤에 알립니다.

## 확인

- 물체가 정보를 담고 있습니다. 화면 내용이 실제이거나 라벨에 실제 값이 있습니다.
- 렌더나 사진의 배경과 슬라이드 바탕 사이에 경계가 보이지 않습니다.
- 그림자와 빛이 한 방향입니다.
- 기기는 정면이거나, 기울였다면 덱에서 한 번이고 각도가 큽니다.
- 오린 인물의 어깨에 세로 경계가 없습니다.
