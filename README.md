# luxurious-design

고급스럽고, 보기 편하고, 기본값으로 찍어 낸 티가 나지 않는 시각 작업물을 만드는 방법을 정리한 문서입니다. 포스터, 발표 자료, 행사 소개서, 표지처럼 한 화면 단위로 보는 작업물이 대상입니다.

실제 작업에서 시안이 반려되고 통과되는 과정을 거치며 찾아본 방법론과, 그때마다 확인된 판단 기준을 모았습니다. 특정 브랜드나 행사에 묶이지 않도록 일반화했습니다.

## 누가 읽으면 좋은가

- 디자이너 없이 포스터나 발표 자료를 직접 만들어야 하는 사람
- AI 도구로 시안을 뽑는데 결과가 어디서 본 듯하게 나오는 사람
- AI 에이전트에게 디자인 작업을 맡기면서 기준 문서를 함께 넘기려는 사람

## 열 가지 규칙

1. 화면마다 주인공을 하나만 정하고, 나머지보다 눈에 띄게 크게 둡니다. 크기 차이가 작으면 평평하게 읽힙니다.
2. 위계는 세 단계에서 끝냅니다. 네 번째 크기가 필요해지면 정보를 덜거나 화면을 나눕니다.
3. 서체는 이유를 말할 수 있는 것으로 고릅니다. 도구가 처음 띄워 주는 서체는 쓰지 않습니다.
4. 강조색은 하나만 쓰고, 한 화면에서 한 곳에만 씁니다.
5. 모든 요소를 그리드의 열 시작선에 맞춥니다. 눈대중 좌표를 두지 않습니다.
6. 묶음은 간격으로 만듭니다. 묶음 사이 간격은 묶음 안 간격의 두 배 이상으로 둡니다. 선과 상자는 간격으로 안 될 때만 씁니다.
7. 사진은 창이나 띠로 자르지 않고 화면 전체에 깝니다. 글자와 피사체를 겹쳐 깊이를 만듭니다.
8. 장식을 넣고 싶은 자리에는 실제 정보를 넣습니다. 날짜, 장소, 규모 같은 사실이 가장 좋은 디테일입니다.
9. 어두운 화면의 본문은 순백 대신 밝은 회색으로 두고, 어두운 색은 파란 기운 없는 중성 회색으로 씁니다.
10. 실제 크기로 렌더링해서 확인합니다. 참고한 작업에서 가져온 구도와 기법을 이름으로 말할 수 있어야 합니다.

## AI 에이전트의 스킬로 쓰기

루트의 [SKILL.md](SKILL.md)는 작업 유형별로 읽을 문서, 반드시 지킬 규칙, 확인 순서, 버전 관리를 한 장에 모은 것입니다. Claude Code에서는 스킬 폴더에 연결해 씁니다.

```bash
git clone https://github.com/danlee-dev/luxurious-design.git ~/luxurious-design
ln -s ~/luxurious-design ~/.claude/skills/luxurious-design
```

## 수치를 읽는 법

문서의 픽셀 수치는 1920×1080 화면을 기준으로 합니다. 다른 크기에서는 긴 변 비율로 환산합니다.

출처가 블로그나 실무 가이드인 수치는 "경험칙"이라고 적었습니다. 그대로 따르기보다 출발점으로 삼고, 실제 화면에서 확인합니다. 접근성 대비 기준처럼 표준 문서에 근거한 수치는 그대로 지킵니다.
